# poker-harness

Разбор покерных рук с **проверенным расчётом**. Турнирный NLHE (MTT с анте), рум GG.
Ключевая граница всей системы: **точное считает код, человеческие пояснения пишет LLM.**
LLM живёт ровно в двух местах — извлечение данных из скриншота и формулировка вердикта.
Арифметику модели не доверяем нигде.

## Прежде чем что-либо публиковать

Репозиторий **публичный**. Не коммитить и не пушить:

- `evals/vision/`, `evals/e2e/` — размеченный eval-датасет (это ров продукта)
- vision-промпты (`src/harness/parsers/prompts/`) — копируются за вечер
- `.claude/screens/` — скриншоты столов
- `fixtures/hh/*.txt` — реальные hand history игрока
- данные пользователей: руки, заметки, инвайт-коды
- секреты: `.env`, токены провайдеров и бота

Обоснование и правило «решение принимается на каждом пуше, а не по дате» —
[docs/publishing-policy.md](docs/publishing-policy.md). Проверяется хуком
`.githooks/pre-push`; на новом клоне включить: `git config core.hooksPath .githooks`.

## Команды

```bash
uv run pytest -q -ra          # -ra обязателен: показывает пропуски
uv run ruff check . && uv run pyright
```

## Фикстуры и цена зелёного прогона

Реальные HH лежат вне репозитория. Без них **5 тестов пропускаются**, включая
регрессионную сетку на 318 руках — главный приёмочный гейт проекта.
**Зелёный прогон без фикстур не означает, что конвейер проверен.** Всегда смотреть
на строку `skipped` в сводке.

## Правило зависимостей

Конвейерные пакеты (`contracts`, `parsers`, `normalizer`, `engine`, `analysis`,
`explanation`, `presentation`) не импортируют ни Телеграм, ни БД, ни `harness.platform`:
данные приходят аргументами, результат возвращается значением. Про инфраструктуру знают
только `bot`, `worker`, `memory`, `platform`.

## Дисциплина, которую легко нарушить незаметно

- **Никогда не выдумывать числа о деньгах.** При расхождении — эскалация игроку
  (скрин = гипотеза) или отказ с логом (hand history = факт), но не «подправить, чтобы сошлось».
- **Судить решение против диапазона, а не против вскрытой карты.** Правильный вход,
  проигравший по случайности, ошибкой не считается.
- **Зона доверия ставится по инструменту, а не по улице.** `strict` — только когда вывод
  не опирается на угаданный диапазон.

## Когда какой документ обязателен к прочтению

Эти документы **не подгружаются автоматически** (вместе они весят ~70 тыс. токенов).
Ниже не оглавление, а условия: если условие выполнено — документ читается до действия,
а не после. Написанное по памяти вместо сверки уже дало в этом проекте четыре
расхождения с библиотекой и одну неверную формулу банка.

| Читать ДО того, как... | Документ |
|---|---|
| решать, где проходит граница сервиса, что считает код, а что излагает LLM, в какой зоне доверия вывод | [.claude/ARCHITECTURE.md](.claude/ARCHITECTURE.md) |
| добавлять любую проверку — надо понять, это тест кода или eval модели (их нельзя смешивать) | [.claude/EVALS.md](.claude/EVALS.md) |
| менять что-либо, что видит пользователь: тексты, кнопки, сессии, квоты | [.claude/SESSIONS_UX.md](.claude/SESSIONS_UX.md) |
| оптимизировать, добавлять кэш, очередь, лимитер — там сказано, что закладывать сразу, а что откладывать до телеметрии | [.claude/SCALING.md](.claude/SCALING.md) |
| трогать контракты, схему БД, выбор библиотеки, провайдер-слой | [тех-спека](docs/superpowers/specs/) |
| реализовывать любую задачу — брать её бриф целиком, а не пересказ | [план](docs/superpowers/plans/) |

**Ограничение этого механизма.** Условие срабатывает только если я его замечу — суждение
отказывает молча. Надёжны лишь механические страховки: pre-push хук, тесты, извлечение
брифа скриптом, ограничения, скопированные ревьюеру дословно. Список выше — подсказка,
а не гарантия; при сомнении дешевле прочитать.
