# Агент: диапазон соперника по чарту и эквити против него (первый срез спеки №3)

Статус: спека на ревью владельца. Решения приняты в диалоге 2026-10-13…14 и записаны здесь.
Опирается на [оболочку агента](2026-10-11-agent-shell-design.md) (спека №1, реализована).

## 1. Зачем

Живой разбор руки (BTN, K♥9♥, флоп 8♦8♥J♠, с-бет 1.8 в банк 5.7, BB колл) показал, чего
агенту не хватает, чтобы ответить на «стоило ли ставить?» так, как это сделал бы тренер.
Владелец написал образец ответа из трёх абзацев. Третий абзац — чтение диапазона по линии:
с чем BB защищается на этом борде и как рука героя стоит против этого. Сейчас агент может
написать такой абзац только из своих знаний покера, а утверждение «K-хай почти всегда
позади» — это эквити против диапазона, которое никто не считал.

Срез делает третий абзац проверяемым: стартовый диапазон соперника даёт чарт, сужение —
агент (допущение, целыми классами), эквити — ядро.

## 2. Решения владельца

| вопрос | решение | дата |
|---|---|---|
| назначение ставки и порог | в сводку разбора — назначение (блеф/полублеф/вэлью…) и порог фолдов из ядра (`postflop_line`); вывод «ставка за фолд-эквити» становится фактом | 2026-10-14 |
| стартовый диапазон | только из чарта; агент сужает, но не придумывает | 2026-10-11 |
| чарт защиты | владелец даёт чарт колла BB против опена BTN; формат как у опен-чартов | 2026-10-14 |
| неполный стол | стол на 7…4 места берёт чарт 8-max, убирая ранние позиции, пока раскладки не совпадут; меньше 4 — свои чарты, без них отказ; это правило, а не допущение | ранее, подтверждено 2026-10-14 |
| сужение | агент правит диапазон целыми классами, помечает «(допущение)» | 2026-10-11 |
| сумма шансов | «бэкдор ≈4% + ≈3% + оверкарта ≈6.5% = 13% эквити» не пишется: шансы пересекаются, оверкарта условна; эквити — только против диапазона, только из ядра | 2026-10-14 |

| первый эталон | эта рука, вопрос и ответ-образец владельца — первый случай `evals/agent/` | 2026-10-14 |

## 3. Что входит

1. Чарты защиты и их лукап (§4), правило неполного стола для опен-чартов и для защиты (§5).
2. Инструмент `opponent_range` — стартовый диапазон соперника по чарту (§6.1).
3. Инструмент `equity_vs_range` — эквити героя против диапазона, заданного агентом (§6.2).
4. Сводка разбора: назначение ставки и порог из ядра (§7).
5. Промпт: форма ответа о ставке из трёх абзацев (§8).
6. Первый эталон (§9).

Не входит: сетка 13×13 в ответе агента, текстура борда (спека B «сегментация»), мультивей
(эквити против нескольких диапазонов), чарты 3-бета и колла не из BB, разбор ривера с
перебором комбо.

## 4. Чарты защиты

Файл `src/harness/analysis/charts/data/defend_8max.json`, схема — опен-чарта
(`open_8max.json`, `schema_version` 3) с двумя отличиями:

```json
{
  "seats": 8,
  "position": "BB",
  "vs_position": "BTN",
  "depth_bb": 25,
  "ante_type": "per_player",
  "call": "…",
  "raise": "…",
  "allin": "…",
  "defend_pct": "…",
  "source": "солвер, 8-max MTT, 25bb (стек до анте), BTN open 2bb, анте …, chipEV",
  "revised_at": "YYYY-MM-DD"
}
```

- Ключ: `(seats, position, vs_position, depth_bb, ante_type)`; глубина — ближайшая, как у опенов.
- Действия: `call`, `raise` (3-бет), `allin`; рука вне всех — фолд; доли одной руки в сумме ≤ 1.
- `defend_pct` — сверка суммы трёх действий, как `open_pct`.
- Провенанс (`source`, `revised_at`) обязателен; данные заполняет владелец, код только читает.
- Загрузчик и лукап — тот же модуль `analysis/charts/lookup.py`, отдельный вид книги
  (`DefendBook` или общий загрузчик с типом чарта — решает реализация, без копии логики
  ближайшей глубины).

Файл с реальными чартами — данные продукта, но не секрет: опен-чарты уже лежат в репозитории.
Владелец решает при первом коммите, коммитить ли `defend_8max.json`.

## 5. Неполный стол

Стол на N мест, 4 ≤ N ≤ 7, берёт запись 8-max той же глубины и анте; позиции сопоставляются
по расстоянию от баттона (с ранних позиций убираются места):

| мест | позиции стола → позиция в чарте 8-max |
|---|---|
| 7 | UTG→UTG+1, UTG+1→LJ, HJ→HJ, CO→CO, BTN→BTN, SB→SB, BB→BB |
| 6 | UTG→LJ, HJ→HJ, CO, BTN, SB, BB — как есть |
| 5 | UTG→HJ, CO, BTN, SB, BB — как есть |
| 4 | UTG→CO, BTN, SB, BB — как есть |

Раскладки — `normalizer.POSITIONS_BY_COUNT`. Меньше 4 мест, 9 мест и больше — только своя
запись, иначе `ChartMissing`. Правило одно для опенов (`open_chart`, вердикт открытия
первым) и для защиты. В выходе инструмента подстановка называется словами («чарт 8-max для
стола на 7 мест»), но допущением не помечается: это решённое правило.

Это меняет поведение существующего вердикта открытия первым на столах 4–7 мест: раньше
`ChartMissing` (без вердикта), теперь вердикт по 8-max. Регрессионная сетка 318 рук
обязана показать, сколько точек получили вердикт впервые; список — владельцу до слияния.

## 6. Инструменты агента

Оба — в закрытом наборе `CalcName`, зона `assuming` у эквити, `strict` у лукапа чарта.

### 6.1 `opponent_range`

Вход от модели: какой соперник (по сводке: его позиция) и какая точка решения (улица).
Код сам определяет из руки: позицию открывшего, линию соперника префлоп (колл / 3-бет),
глубину соперника в BB, число мест, анте. Модель эти величины не передаёт.

Выход: строка диапазона (компактная запись), доля рук (`fraction_of_hands`), число комбо
с учётом карт героя и борда, источник («чарт защиты BB против BTN, 8-max, 25 BB»). Нет
записи — отказ словами («чарта для этого спота нет»), и агент не подставляет свой диапазон.

Префлоп-линии вне чартов (лимп, колл 3-бета, сквиз) в этом срезе — отказ.

### 6.2 `equity_vs_range`

Вход от модели: диапазон строкой (классы, без весов), улица (борд берётся из руки), руки
героя берутся из руки.

Правила кода:
- **Подмножество.** Каждый класс должен быть в стартовом диапазоне этого соперника
  (`opponent_range` той же точки) с ненулевой долей; иначе отказ «этих рук нет в стартовом
  диапазоне». Так сужение остаётся сужением, а не новым диапазоном.
- **Целые классы.** Веса чарта сохраняются как есть у оставленных классов; агент веса не
  задаёт.
- Мёртвые карты (герой, борд) исключаются из комбо.
- Детерминизм: фиксированный `seed`, потолок итераций (значение — реализация, по замеру
  времени на стенде; кэш `calc_cache`).

Выход: эквити героя, число комбо суженного диапазона, доля комбо от стартового, разбивка
стартового диапазона «что убрано» не нужна. Зона `assuming`: в выходе строка «диапазон
сужен агентом — это допущение».

Сверка чисел (`check_agent_answer`) принимает числа этих выходов как числа расчёта.

## 7. Сводка разбора: назначение и порог

`agent_context` добавляет для каждой постфлоп-точки героя строку из `postflop_line`:
назначение («блеф», «полублеф», «вэлью», «ставка со средней рукой»…) словами разбора и
порог фолдов (`FoldThreshold.bluff`, у полублефа и `semibluff`, признак «окупается без
фолдов»). Числа регистрируются в `NumberBook`.

После этого модели не нужен `defense_frequency` для своей ставки: порог уже в сводке.
Промпт: для ставки героя брать порог из сводки; `defense_frequency` — для вопросов о
чужой ставке или произвольного размера.

## 8. Промпт: ответ о прибыльности ставки

Форма по образцу владельца — до трёх абзацев:
1. Порог из сводки → статистика по уровню данных (соперник / поле в позиции / поле в
   целом) → вывод «в плюсе / в минусе» только при решённом сравнении → назначение ставки
   из сводки.
2. Эквити героя при колле: шансы из сводки по отдельности, без суммы; «реальный порог ниже»
   — словами, без числа.
3. Диапазон соперника: стартовый по `opponent_range` → сужение по линии (классы, пометка
   «(допущение)») → эквити против суженного по `equity_vs_range`. Нет чарта — абзац
   короткий: «чарта для этого спота нет, диапазон не оцениваю».

## 9. Первый эталон

`evals/agent/cases/` (каталог закрыт pre-push хуком — добавить `evals/agent/` в
`FORBIDDEN_PATHS`): рука по ссылке на её разбор в базе или выгрузка нормализованной руки,
вопрос «что думаешь про контбет флопа? стоило ставить?», ответ-образец владельца
(исправленный: без «13%», третий абзац с числами расчёта), обязательные расчёты
(`frequency_vs_threshold` по полю в BB, `opponent_range`, `equity_vs_range`), запреты
(сумма шансов, эквити без расчёта, величины соперника без вопроса). Прогонщик и судья —
спека №2; здесь только данные и формат.
