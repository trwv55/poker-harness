# poker-harness

Разбор покерных рук с **проверенным расчётом**: движок правил пересчитывает и валидирует
каждую руку, математику считает код, LLM только излагает результат словами. Турнирный
NLHE (MTT с анте), рум GG (PokerCraft). В разработке.

## Состояние

Готова первая ступень — конвейер от файла hand history до проверенной руки:

```
HH-файл → HHParser → HandNormalizer → Hand engine (PokerKit + валидатор) → EnrichedHand
```

На двух реальных турнирах (318 рук) конвейер даёт вердикт `pass` на всех руках,
пересчитанный банк совпадает с записью рума, сохранение фишек и структура сайд-потов
сходятся. Аналитического ядра (эквити, ICM, пуш-фолд, разбор решений) ещё нет — это
следующий этап.

### Публикация

Репозиторий открыт до выхода продукта. Что в него не попадает и почему — в
[docs/publishing-policy.md](docs/publishing-policy.md); правило проверяется хуком
`pre-push`, который включается на клоне один раз:

```bash
git config core.hooksPath .githooks
```

### Фикстуры

Регрессионная сетка гоняется на реальных hand history — это приватные данные игрока,
и в репозиторий они не входят. Без файлов в `fixtures/hh/` тесты, зависящие от них,
**пропускаются**, о чём прогон сообщает явно (`-ra`).

Это значит: **зелёный CI не равен проверенному конвейеру.** Полный гейт на 318 руках
выполняется только локально, там где файлы есть. Чтобы его включить, положите
экспортированные из PokerCraft файлы турниров в `fixtures/hh/` под именами
`daily-classic-146.txt` и `pko-bounty-172.txt` (числа в именах — количество рук,
которое ожидает сетка).
